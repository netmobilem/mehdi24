# 🛰️ TiTaN Panel

پنل مدیریت حرفه‌ای برای نودهای **Xray + Nginx** — با هسته‌ی ترکیبی، داشبورد دقیقاً طبق طراحی تأییدشده، حسابداری ترافیک واقعی، لینک‌های اشتراک و QR، به‌همراه ایجنت سبک روی هر سرور.

> این پروژه **از صفر** نوشته شده است؛ نه فورک است و نه کپی از هیچ پنل دیگری. معماری، مدل داده، تولیدکننده‌ی کانفیگ، ایجنت، API و رابط کاربری همه در همین مخزن طراحی و پیاده‌سازی شده‌اند.

---

## ✨ چرا این پنل

| | |
|---|---|
| 🧩 **هسته‌ی ترکیبی Xray + Nginx** | Nginx مالک TLS، ALPN، HTTP/2، سایت پوششی و ضد‌کاوی است؛ Xray مالک پروتکل‌ها و تونل. ترافیک با `proxy_protocol` می‌رسد، پس **IP واقعی کاربر** همیشه در دست است. |
| ⚡ **بهینه برای سرعت و پینگ** | BBR، TCP Fast Open، `epoll` + `reuseport`، `tcp_nodelay`، بافر صفر روی مسیرهای پروکسی، tune شدن کرنل و nginx به‌صورت خودکار روی هر نود. |
| 🔐 **TLS یا REALITY، دلخواه** | گواهی Let's Encrypt با چالش HTTP-01 یا REALITY با کلیدهایی که همان لحظه در پنل ساخته می‌شوند. |
| 🧠 **استقرار امن** | هر تغییر قبل از اعمال با `xray -test` و `nginx -t` اعتبارسنجی می‌شود؛ در صورت خطا **خودکار به کانفیگ قبلی برمی‌گردد** (rollback). |
| 📊 **آمار واقعی** | مصرف هر کاربر از Stats API خود Xray خوانده می‌شود (نه تخمین)، در باکت‌های ساعتی ذخیره و روی نمودار روزانه/ساعتی نشان داده می‌شود. |
| 🚦 **کنترل کامل مشتری** | حجم، انقضا، حد دستگاه (IP هم‌زمان)، حد سرعت (Mbps)، چرخه‌ی ریست، غیرفعال‌سازی خودکار روی عبور از حد. |
| 🔗 **اشتراک حرفه‌ای** | لینک base64، خروجی Clash، JSON، صفحه‌ی عمومی با QR، رمز اختیاری، هدرهای `subscription-userinfo` برای کلاینت‌ها. |
| 🤖 **بدون وابستگی سنگین** | ایجنت نود **فقط با پایتون استاندارد** اجرا می‌شود (بدون pip) — نصب روی سرور خام تقریباً هیچ‌وقت شکست نمی‌خورد. |

## 🏗️ معماری

```
                    ┌──────────────── نود (سرور) ─────────────────┐
   کاربر            │                                             │
     │  TLS 443      │   ┌────────┐   ┌──────────────┐             │
     └──────────────►│   │ Nginx  │──►│ Nginx (https)│──┐          │
        (SNI route) │   │ stream │   │  8443 decoy  │  │          │
                     │   └───┬────┘   └──────────────┘  │          │
                     │       │ SNI = REALITY            │ /path    │
                     │       ▼                          ▼          │
                     │   ┌──────────────────────────────────────┐  │
                     │   │   Xray-core  (inbounds روی 127.0.0.1)│  │
                     │   └──────────────────────────────────────┘  │
                     │                ▲                            │
                     │   ┌────────────┴───────────┐                │
                     │   │ TiTaN Agent :62050     │◄── پنل (SSH/HTTP)
                     │   └────────────────────────┘                │
                     └─────────────────────────────────────────────┘
                                       ▲
                          ┌────────────┴─────────────┐
                          │      TiTaN Panel         │  Railway / Docker / VPS
                          │ FastAPI + SQLite + UI    │
                          └──────────────────────────┘
```

سه حالت مسیر‌دهی برای هر کانفیگ (خودکار انتخاب می‌شود):

| حالت | ترابری‌ها | چه اتفاقی می‌افتد |
|---|---|---|
| `fronted` | WS · XHTTP · gRPC · HTTPUpgrade | Nginx روی ۴۴۳ TLS را تمام می‌کند و مسیر را به inbound محلی Xray می‌فرستد |
| `passthrough` | REALITY | Nginx با `ssl_preread` فقط SNI را می‌خواند و بایت‌ها را دست‌نخورده به Xray می‌دهد |
| `direct` | TCP · QUIC · Hysteria2 · WireGuard | خود Xray روی یک پورت اختصاصی (خارج از ۴۴۳) گوش می‌دهد |

جزئیات بیشتر: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)

## 🚀 نصب

### ۱) پنل روی Railway (سریع‌ترین راه)

1. این مخزن را در حساب گیت‌هاب خودتان قرار دهید و در Railway → **New Project → Deploy from GitHub** آن را انتخاب کنید.
2. در سرویس، یک **Volume** بسازید و روی مسیر `/data` وصل کنید (بدون این کار، اطلاعات با هر ری‌استارت پاک می‌شود).
3. متغیرهای محیطی را تنظیم کنید:
   - `ADMIN_PASSWORD` — رمز ورود ادمین (اجباری)
   - `SECRET_KEY` — اختیاری (خالی بماند، خودکار ساخته و در Volume ذخیره می‌شود)
4. **Settings → Networking → Generate Domain** تا `RAILWAY_PUBLIC_DOMAIN` پر شود (لینک‌های اشتراک از همین دامنه ساخته می‌شوند).
5. **پورت:** پنل هم‌زمان روی `PORT` (که Railway خودش تزریق می‌کند) **و** `EXTRA_PORTS` (پیش‌فرض `8080`) گوش می‌دهد — هم روی IPv4 و هم IPv6. پس خطای
   «Application failed to respond» که از اختلاف **پورت هدف دامنه** با پورت اپ می‌آید دیگر رخ نمی‌دهد: پورت هدف دامنه را `8080` بگذارید.
   در لاگ دیپلوی خط `TiTaN is listening on: …` دقیقاً پورت‌های فعال را نشان می‌دهد و `/healthz` هم فیلد `listen` را برمی‌گرداند.
   برای پورت‌های بیشتر: `EXTRA_PORTS=8080,3000` — برای خاموش کردن: `EXTRA_PORTS=`

### ۲) پنل روی VPS با یک فرمان

```bash
curl -fsSL https://raw.githubusercontent.com/<you>/titan-panel/main/deploy/install-panel.sh | sudo bash
```

یا با Docker:

```bash
cp .env.example .env && nano .env      # رمز ادمین را عوض کنید
docker compose up -d --build
```

### ۳) نود (سرور پروکسی)

در پنل: **سرورها → افزودن سرور** → دامنه/آی‌پی و مشخصات SSH را وارد کنید → دکمه‌ی **نصب خودکار**.

ایجنت روی سرور این کارها را انجام می‌دهد:

1. نصب `nginx` (کامل، با ماژول stream) و **Xray-core** از مخزن رسمی XTLS
2. `sysctl`: BBR، fq، TFO، بازه‌ی پورت، بافرها، file-max
3. ساختار مسیرها: `/etc/titan/tls`، `/etc/nginx/conf.d/titan`، `/var/www/titan-decoy`
4. فایروال: فقط ۲۲/۸۰/۴۴۳ + پورت‌های اختصاصی inboundهای `direct` + پورت ایجنت
5. سرویس systemd ایجنت + اعتبارسنجی سلامت

اگر SSH ندارید: از صفحه‌ی سرور، دکمه‌ی **اسکریپت دستی نصب** فایل bash را دانلود و روی سرور اجرا کنید (همان کارها را انجام می‌دهد).

## 🌍 انتخاب نود برای کمترین پینگ

سرعت و پینگ فقط تابع کانفیگ نیست؛ محل و کیفیت مسیر مهم‌تر است. تجربه‌ی عملی برای کاربران ایران:

| هدف | بهترین انتخاب | چرا |
|---|---|---|
| کمترین پینگ | **ترکیه (استانبول)**، **امارات (دبی)**، **ارمنستان/گرجستان** | مسیر کوتاه، بدون عبور از چند نقطه‌ی تبادل |
| پینگ متوسط + پایداری خوب | **آلمان (فرانکفورت)**، **هلند (آمستردام)**، **فنلاند** | پهنای‌باند ارزان، مسیر پایدار به اروپا |
| سرور مقصد سرویس‌ها (AI/استریم) | آمریکا/کانادا به‌عنوان **خروجی زنجیره‌ای** | پینگ کاربر به نود نزدیک می‌ماند، خروجی از آن‌سو |

نکته‌ها:
- روی هر نود **BBR + fq** را ایجنت خودکار فعال می‌کند؛ اگر ارائه‌دهنده BBR را غیرفعال کند، سرعت به‌شدت افت می‌کند.
- برای هر کانفیگ ترابری مناسب انتخاب کنید: **XHTTP (stream-up)** روی شبکه‌های پرافت، **WS/http1.1** روی شبکه‌های سخت‌گیر، **REALITY** وقتی گواهی یا دامنه ندارید.
- برای کاربران موبایل، ALPN را `h2,http/1.1` بگذارید تا QUIC/H2 مسیر بهتری پیدا کند؛ برای شبکه‌های محدود `http/1.1` پایدارتر است.
- همه‌ی نودها را در **یک دامنه** سرویس ندهید؛ برای هر نود زیر‌دامنه‌ی مستقل بسازید تا نویز SNI کمتر شود.

## 🔧 پشتیبانی پروتکل و ترابری

| پروتکل | ترابری‌ها | امنیت | توضیح |
|---|---|---|---|
| VLESS | WS · XHTTP (packet-up/stream-up/stream-one) · gRPC · TCP | TLS · REALITY · none | حالت پیشنهادی مدرن: **VLESS + XHTTP** |
| VMess | WS · XHTTP · gRPC · TCP | TLS · REALITY | سازگاری با کلاینت‌های قدیمی‌تر |
| Trojan | WS · XHTTP · TCP | TLS | ساده و پایدار |
| Shadowsocks | TCP | none · TLS | روش ۲۰۲۲ با کلید خودکار |
| Hysteria2 | QUIC/UDP | TLS | برای لینک‌های پرافت و پرتأخیر (اختیاری) |
| WireGuard | UDP | — | پروفایل کامل کلاینت تولید می‌شود (اختیاری) |

> نکته‌ی مهم نسخه‌های جدید Xray: ترابری‌های WS/gRPC و پروتکل‌های Trojan/VMess/Shadowsocks در Xray 26 «legacy» علامت خورده‌اند و پیشنهاد رسمی، **VLESS + XHTTP** است. پنل هر دو را پشتیبانی می‌کند و پیشنهاد می‌کند برای کانفیگ‌های جدید از XHTTP استفاده کنید.

هر کانفیگ این پارامترها را جدا دارد: پورت عمومی، مسیر، Host، SNI، **ALPN**، **Fingerprint (uTLS)**، Flow، حالت XHTTP، مقصد و serverNames برای REALITY.

## 🔌 API

| متد | مسیر | کاربرد |
|---|---|---|
| `GET` | `/healthz` | پایش سلامت پنل و کارگرها |
| `GET` | `/api/docs` | مستندات OpenAPI |
| `GET` | `/api/dashboard` | داده‌ی زنده‌ی داشبورد (JSON، برای پولینگ مرورگر) |
| `GET` | `/api/config-preview` | پیش‌نمایش کانفیگ Xray هر نود |
| `GET` | `/sub/{token}` | بدنه‌ی اشتراک (base64 + هدرهای استاندارد) |
| `GET` | `/sub/{token}/clash.yaml` | خروجی Clash Meta |
| `GET` | `/sub/{token}/json` | خروجی JSON |
| `GET` | `/s/{token}` | صفحه‌ی عمومی اشتراک با QR (رمز اختیاری) |

**API ایجنت روی نود** (با هدر `X-Titan-Token`): `GET /health`, `GET /stats`, `GET /ips`, `GET /logs`, `POST /apply`, `POST /cert`, `POST /shaping`, `POST /exec`.

## 🔐 نکات امنیتی

- رمز ادمین را بعد از اولین ورود از **تنظیمات → تغییر رمز** عوض کنید.
- پورت ایجنت را از اینترنت ببندید یا با فایروال فقط به آی‌پی پنل اجازه بدهید؛ توکن ایجنت در `/etc/titan/agent.token` است.
- `PANEL_ALLOWED_IPS` را تنظیم کنید تا پنل فقط از شبکه‌ی خودتان باز شود.
- پورت `8443` عمداً بسته می‌ماند؛ فقط از مسیر `443` (stream) قابل دسترسی است تا امکان عبور از فیلتر و کاوش کاهش یابد.
- کلید `SECRET_KEY` و فایل `/data/titan.key` را محرمانه نگه دارید (امضای نشست‌ها بر پایه‌ی آن است).
